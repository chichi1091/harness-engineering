# Security Review

変更差分をセキュリティ観点でレビューするための専門手順。

## 手順

1. **入力境界**: 外部入力の検証・エスケープ漏れを確認する。
2. **認証・認可**: 認可漏れ・権限昇格の可能性を確認する。
3. **秘密情報**: ハードコードされた credential、ログへの漏洩経路を確認する。
4. **依存関係**: 既知の脆弱性バージョンを使用していないか確認する。
5. **報告**: 指摘は `severity` 付きで review-result に記録する(非Blocking原則に従う)。

## 制約

- 根拠のない憶測による指摘をしない
- 実装コードをレビュー中に変更しない(Reviewerの制約に従う)
