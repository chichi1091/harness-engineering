# Unit Test Design

受入条件をテスト観点へ変換し、単体テストを設計・実装するための専門手順。

## 手順

1. **分解**: 受入条件を1つずつテスト観点(正常系・異常系・境界値)へ対応付ける。
2. **設計**: 各観点に対するテストケースを具体化し、期待結果を明示する。
3. **実装**: 既存テストの構成に従いテストを追加する。既存テストの意図は変更しない。
4. **記録**: 実行結果と未検証領域を test-result Artifact の `tests` に記録する。

## 制約

- テスト不能な受入条件は Test Engineer の制約に従い差し戻し理由として報告する
- 実装コードをテストのために変更する場合は理由を記録する
